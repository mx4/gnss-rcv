# Performance: CPU-cost optimizations

A living catalogue of what keeps the receiver fast enough to run at (or near)
real time, organised by pipeline stage. Each entry says *what* it does, *where*
it lives, and *why* it helps. Acquisition dominates the cost, so most of the
leverage is there.

Rule of thumb when touching this: **measure on the target (Apple M3 / NEON)**,
not from x86/AVX intuition — see [the optimize-hot-paths memory] and the
"measured wins" notes below. Cold paths stay simple on purpose.

## Ingest

- **Wideband decimation** — `src/decimate.rs` (`DecimatingReader`,
  `decimation_factor`). Wideband captures are FIR low-passed and integer-
  decimated to the lowest rate that still carries the signal band before
  anything else sees them (tuni2025: 50 → 6.25 Msps, k=8). Everything
  downstream — FFTs, carrier tables, correlators — then runs at `fs/k`, so the
  whole receiver costs ~k× less. `GNSS_DECIM=off` disables for A/B runs. Full
  rationale in [ingest-decimation.md](ingest-decimation.md).

## Scheduling / stepping

- **Per-family scheduler grids** — `src/scheduler.rs`. Each signal family steps
  on its own code-period grid (C/A every 1 ms, E1 every 4 ms); only the *due*
  family's channels process on a given block. No wasted work re-stepping a
  family that hasn't advanced a code period. See
  [multi-signal-stepping.md](multi-signal-stepping.md).

## Acquisition (the dominant cost)

- **Shared per-block FFT cache** — `src/receiver.rs` (`process_step`, the
  `bins[..].par_iter_mut()` build). The carrier-mixed forward FFT for each
  Doppler bin is PRN-independent, so it is computed **once per family step** and
  reused by every channel searching that block. Per-PRN work then collapses to a
  pointwise multiply + IFFT (`finish_correlation_inplace`).
- **Shared carrier replicas** — `Channel::build_carriers`. One set of
  per-Doppler-bin carrier tables per family, shared across all its channels.
  Avoids both the per-sample sin/cos and the per-PRN duplication that OOM'd at
  50 Msps (~8.6 GB → shared).
- **Parallelism (rayon)** — Doppler bins (`par_iter_mut` over the cache) and
  channels (`self.channels.par_iter_mut()` in `process_step`) both run in
  parallel. Acquisition and tracking are dispatched concurrently across
  channels.
- **LO-offset Doppler narrowing** — `src/channel.rs` (`acquisition_init`,
  `ACQ_SPREAD_LO_KNOWN_HZ`, `SBAS_DOPPLER_SPREAD_HZ`, `ACQ_LO_MIN_SVS`). The
  ±12 kHz sweep exists for the unknown front-end LO offset, which is common to
  all SVs. Once ≥`ACQ_LO_MIN_SVS` (3) channels track, the median of their
  Dopplers estimates the LO and every search shrinks to LO ± 6 kHz (MEO) /
  ±3 kHz (SBAS GEO). This narrows both the FFT-cache union *and* the per-PRN
  grids. (Gated at 3 SVs because a single lock's Doppler is LO + that SV's own
  ±5 kHz motion, which would mis-centre the window — see the const comment.)
- **Acquisition admission cap** — `MAX_CONCURRENT_ACQ` (= 8). Bounds how many
  channels hold a `sum_p` search grid at once; a cold start would otherwise
  allocate one grid per absent PRN (~1 GB at 50 Msps). A slot frees the instant
  a search locks or fails (≤ T_ACQ), so coverage costs ~ceil(N/cap)·T_ACQ, not
  sensitivity. Admission order has a deterministic SV tie-break (reproducible
  runs).
- **Idle backoff** — `idle_process`. PRNs that keep failing acquisition idle
  progressively longer (linear, capped at `T_IDLE_MAX`); a successful lock
  resets the counter. SBAS idles longer from the start and stops searching
  entirely once `SBAS_TRACKED_ENOUGH` (2) GEOs track.
- **Right-sized, transient grids** — the `sum_p` grid is `f32` and sized to the
  *current* attempt's searched bin range, and is freed on lock/idle (not held
  full-width for channels that are tracking or absent).

## Tracking

- **8-lane carrier mixing** — `src/util.rs` (`doppler_shift`). The carrier is
  generated by an f64 phase recurrence (one complex multiply/sample instead of a
  sin/cos). The serial recurrence is a loop-carried dependency and was the
  single most expensive tracking op on M3; running `LANES = 8` independent phase
  accumulators (block strided by `step^8`) pipelines it for ~2.2× — output
  bit-identical to the serial form.
- **Single fused correlation pass** — `src/channel.rs`
  (`tracking_compute_correlation`). Prompt, early, late and the noise reference
  are accumulated in one pass over the code period, reading `sig[j]`/`code[j]`
  once each, instead of four separate passes.
- **Real-code multiply** — the spreading code is real (±1), so `sig·code` is two
  scalar f32 multiplies, not a full complex product. f32 multiplies, f64
  accumulators (the f64 reduction guards ~3 significant digits over 50k samples;
  a prior attempt to vectorise this further regressed on M3).
- **Diagnostics gating** — headless runs keep only a tiny history ring
  (`HISTORY_MIN`) and skip the 2 s per-channel snapshot clone; the full history
  is kept only under `--plots` or the egui UI (`diagnostics` flag).

## Solver

- **Fix cadence gate** — `src/receiver.rs` (`compute_fix`): the solver runs at
  most once every 2 s of *data* time, regardless of step rate.
- **Cross-correlation rejection** — duplicate-ephemeris SVs (cross-correlation
  phantom locks) are dropped before the solve (`reject_cross_correlations`).

## FFT

- **rustfft** with NEON kernels on ARM; plans are cached in a `FftPlanner` and
  reused, not re-planned per call.

## Candidates / not yet done

Ideas evaluated but not (yet) implemented — kept here so we don't re-litigate
them from scratch:

- **Almanac / position-aided acquisition** — the big one for multi-constellation
  (e.g. Galileo's 36 PRNs). With a (cached or post-fix) position + ephemeris,
  subtract each SV's *predicted* Doppler to get a pure LO from a single lock, and
  skip SVs below the horizon entirely. Would shrink per-SV windows from ±6 kHz to
  ±a few hundred Hz and cut ~⅔ of PRNs from the search. The LO-median narrowing
  above is the cheap, no-ephemeris stand-in.
- **Two-stage coarse→fine Doppler** — cheap wide-bin scan to localise, fine scan
  only near hits. Helps cold start (LO unknown) with no external data.
- **Galileo E1C pilot acquisition** — acquire on the dataless pilot for longer
  coherent integration (fewer non-coherent sums per SV); needs CS25 secondary-
  code handling. Sensitivity *and* speed.
- **QZSS narrower Doppler** — QZSS (PRN 193–202) is IGSO/GEO, not MEO, but is
  currently lumped into the GPS L1CA path and inherits the MEO ±6 kHz search; it
  could use an SBAS-like narrow window.
- **Decimation FIR SIMD** — `decimate.rs`'s tap loop has a per-tap bounds branch
  and reversed indexing that block clean autovectorisation; a branchless
  steady-state pass over pre-reversed taps would emit NEON FMA. Only matters for
  wideband (decimated) captures; profile first.
- **`lto = true` + `codegen-units = 1`** in `[profile.release]` — cross-crate
  inlining (rustfft, DSP helpers); typically 5–15% on compute-bound code, at the
  cost of slower release links. `target-cpu=native` is marginal on Apple Silicon
  (NEON is baseline).
